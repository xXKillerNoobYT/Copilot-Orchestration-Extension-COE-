# Multi-Format Export - Manual Testing Guide

## Overview
This guide provides instructions for manually testing the new multi-format export functionality added in EPIC-011.

## Prerequisites
1. VS Code with Copilot Orchestration Extension installed
2. A test plan created in Plan Builder
3. Write access to a local directory for exports

## Test Scenarios

### 1. Enhanced Markdown Export

**Steps:**
1. Open VS Code
2. Open Plan Builder panel
3. Create or open an existing plan
4. Run command: `Copilot Orchestrator: Export Plan`
5. Select "Enhanced Markdown" format
6. Choose an output directory
7. Verify file is created

**Expected Results:**
- File named `[PlanName]-enhanced.md` is created
- File contains:
  - Professional cover page with project metadata
  - Table of contents with clickable links
  - Mermaid dependency diagram with color-coded priorities
  - Mermaid Gantt chart timeline
  - Feature tables with priorities and estimates
  - Architecture section with components
  - Team structure with roles and skills
  - Risks table with mitigation strategies
  - Success criteria, assumptions, and constraints

**Validation:**
- Open the markdown file in VS Code preview
- Verify Mermaid diagrams render correctly
- Check all sections are present and formatted properly
- Verify links in TOC work

---

### 2. PDF Export (Advanced)

**Steps:**
1. Open Plan Builder panel
2. Create or open an existing plan
3. Run command: `Copilot Orchestrator: Export Plan`
4. Select "PDF Advanced" format
5. Choose an output directory
6. Verify file is created

**Expected Results:**
- File named `[PlanName]-plan.pdf` is created
- PDF contains:
  - Professional cover page with title, version, author
  - Project overview section
  - Architecture details
  - Features list with priorities and descriptions
  - Timeline with milestones
  - Team structure
  - Risks and mitigation strategies
  - Page numbers on every page
  - Footer: "Generated by Copilot Orchestration Extension"

**Validation:**
- Open PDF in a PDF reader (Adobe Reader, Preview, etc.)
- Verify all pages are present
- Check text is readable and properly formatted
- Verify page breaks are appropriate
- Confirm cover page looks professional
- Check footer appears on all pages

---

### 3. Figma Export

**Steps:**
1. Open Plan Builder panel
2. Create or open an existing plan
3. Run command: `Copilot Orchestrator: Export Plan`
4. Select "Figma Export" format
5. Choose an output directory
6. Verify file is created

**Expected Results:**
- File named `[PlanName]-figma.json` is created
- JSON contains:
  - Design tokens section with:
    - Colors (primary, secondary, semantic)
    - Typography (font families, sizes, weights, line heights)
    - Spacing scale
    - Border radius values
  - Components array (one per feature)
  - Layouts array

**Validation:**
- Open JSON file in VS Code or JSON viewer
- Verify JSON is valid (no syntax errors)
- Check color palette includes shades 50-900 for primary/secondary
- Verify typography includes common font sizes (xs, sm, base, lg, xl, etc.)
- Confirm each plan feature has a corresponding component
- Check components have name, category, variants, and props
- Verify layouts include grid and flex definitions

---

### 4. OpenAPI Export

**Steps:**
1. Open Plan Builder panel
2. Create or open an existing plan
3. Run command: `Copilot Orchestrator: Export Plan`
4. Select "OpenAPI Specification" format
5. Choose an output directory
6. Verify file is created

**Expected Results:**
- File named `[PlanName]-openapi.json` is created
- JSON contains:
  - `openapi: "3.0.0"` version
  - Info section with title, version, description, contact
  - Servers array with production and staging URLs
  - Paths object with at least `/plan` endpoint
  - Feature-specific endpoints (`/features/{id}`)
  - Components.schemas with Plan, Feature, Milestone definitions
  - Tags array matching plan features

**Validation:**
- Open JSON file in VS Code or JSON viewer
- Verify JSON is valid
- Check OpenAPI version is "3.0.0"
- Verify info section matches plan metadata
- Confirm paths include GET operations
- Check schemas have proper type definitions
- Verify required fields are marked in schemas
- Validate enums are present (priority, status, etc.)

**Optional Swagger Validation:**
- Visit https://editor.swagger.io/
- Copy JSON content
- Paste into Swagger Editor
- Verify no validation errors
- Check API documentation renders correctly

## Edge Cases to Test

### Special Characters in Plan Name

**Test:**
1. Create plan with name: `Test/Plan: Special*Chars?`
2. Export to all formats
3. Verify filenames are sanitized

**Expected:**
- Forbidden characters `<>:"|?*\/\` replaced with underscores
- Spaces replaced with hyphens
- Example: `Test_Plan_-Special_Chars_-plan.pdf`

### Empty Features/Risks

**Test:**
1. Create plan with no features
2. Export to all formats
3. Verify graceful handling

**Expected:**
- Enhanced Markdown shows "_No features defined yet._"
- PDF includes section but notes it's empty
- Figma has empty components array
- OpenAPI has minimal paths (just `/plan`)

### Large Plan

**Test:**
1. Create plan with 50+ features
2. Export to PDF
3. Verify pagination works correctly

**Expected:**
- PDF properly spans multiple pages
- No text cutoff
- Page numbers accurate
- Footer on every page

## Integration Testing

### Export Multiple Formats

**Test:**
1. Export same plan to all formats sequentially
2. Verify all files are created
3. Compare content consistency

**Expected:**
- All formats export successfully
- Plan name consistent across formats
- Feature count matches in all exports
- No file conflicts or overwrites

---

## Error Handling

### Invalid Output Path

**Test:**
1. Select non-existent directory
2. Attempt export

**Expected:**
- Error message displayed
- No file created
- User prompted to select valid directory

### Permission Denied

**Test:**
1. Select read-only directory
2. Attempt export

**Expected:**
- Error message about permissions
- User-friendly error notification
- Suggestion to choose different directory
